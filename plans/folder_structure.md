### Key Structural Changes (vs Fastify approach)

| Concept | Fastify | Express (Current) |
|---|---|---|
| **Route files** | `routes.ts` (Fastify route object) | `router.ts` (Express Router — portable) |
| **Plugins** | `plugins/` directory (Fastify plugin system) | `middleware/` directory (standard Express middleware) |
| **Validation** | JSON Schema (Fastify built-in) | Zod schemas + `validate.ts` middleware |
| **WebSocket** | `@fastify/websocket` (plugin) | `ws/` directory (standalone `ws` server) |
| **Service extraction** | Requires rewriting plugin → standalone app | Copy router + `express().listen()` — done |

### Key Structural Changes (Next.js → React + Vite)

| Concept | Next.js (App Router) | React + Vite (Current) |
|---|---|---|
| **Entry point** | `app/layout.tsx` (root layout) | `src/main.tsx` + `index.html` |
| **Routing** | File-based (`app/page.tsx`, `[id]/page.tsx`) | `react-router-dom` config in `router.tsx` |
| **Layouts** | Nested `layout.tsx` files | Layout wrapper components (`AdminLayout.tsx`) |
| **Auth guards** | `layout.tsx` with redirect | `<AuthGuard>` and `<RoleGuard>` components |
| **Dynamic params** | `[id]` folders | `:id` route params via `useParams()` |
| **Data fetching** | `fetch()` in Server Components | SWR hooks in client components |
| **SSR** | Built-in (adds complexity) | None — pure SPA (simpler, fully decoupled) |
| **Build output** | Node.js server | Static HTML/JS/CSS (served by Nginx) |
| **Dev server** | `next dev` (:3000) | `vite dev` (:5173) with API proxy |
